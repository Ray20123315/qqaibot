# QQ 官方指令選單：移除過期的「设置插话率」

## 已查明

使用者在 QQ 的 AIBot 原生指令選單看到「/!设置插话率」、「查看主动插话暂停状态」，但目前 QQAIBOT 精簡 AI 程式並未註冊這條指令，也不存在「主動插話率」管理功能。最新回歸測試會檢查 `worker.js`、`src/abot-ai.js`、`src/assistant.js` 和 `src/core.js` 不重新註冊這些舊名稱。

**QQ 輸入框由 QQ 客戶端展示的「/」建議並非普通 Bot 回覆文字**。QQ 官方開發文件指出，開發者在機器人管理端的「發布設定 → 功能配置 → 指令配置」新增／移除的指令會顯示於 QQ 群、單聊等原生指令面板。因此只部署 Worker 或在程式裡刪指令，不能保證已發布的舊選單項目消失。

## 必須對 QQ 官方管理端清理

1. 使用 AIBot 對應的 QQ 開放平台開發者帳號登入 [QQ 機器人開放平台](https://q.qq.com/)。
2. 開啟 AIBot 的「發布設定」→「功能配置」→「指令配置」（依新版後台名稱可能略有不同）。
3. 找出名為 `!设置插话率` 或 `设置插话率` 的舊指令，以及說明「查看主动插话暂停状态」的項目。
4. 刪除這條舊指令，只保留新版仍有效且使用者確實需要的入口；按頁面提示確認／重新發布。
5. QQ 客戶端重新進入聊天、重新開啟指令建議，確認舊指令不再出現。若仍在，檢查其他「指令面板」或「快捷選單」配置和客戶端快取。

這是 QQ 開放平台**發布資料**的管理動作，目前沒有已連線的 QQ 官方後台操作工具，也未核對到該筆發布資料的 ID，因此不能聲稱已從平台刪除。不要因這條過期指令去修改 Bbot 群設定、AI 模型、Secret 或 D1。

參考：QQ 官方 `tencent-connect/bot-docs` 的「發布設定 / 功能配置 / 指令配置」說明，以及 QQ 指令面板管理 API。

## 自動清理實作（2026-10-11 補充）

除了上述 QQ 管理端手動移除方式，目前 QQ 官方已提供 `/v2/panels` 查詢、更新、刪除 API。本專案新增一次性清理任務：`src/qq-panel-cleanup.js` 只匹配 `设置插话率`（容許前綴 `/!`），對含有其他指令的面板只更新並保留其他項目；當面板唯一項目就是此過期指令時才刪除空面板，不改其他指令名稱、說明、權限或關聯範圍。

Worker 的 `QQ_RETIRED_COMMAND_CLEANUP=true` 配合原有 Abot Gateway Durable Object，每次最少間隔 15 分鐘，成功後只執行一次，狀態記錄在 Durable Object storage。可透過 `/health` 的 `abot.command_panel_cleanup` 查看：
- `removed`：QQ API 已成功更新或刪除含舊指令的面板（需確認前端刷新）。
- `no_match`：新式面板沒有找到它，QQ 客戶端可能引用舊發布設定，依上一節到開放平台管理端刪除。
- `failed`：QQ API 權限、參數或連線錯誤，需要核查 Worker 安全錯誤碼，不得宣稱已清理。
- `pending`：尚未執行或已部署但 Cron 尚未觸發。

此流程不是重建全部面板，且不會更動 AI／Codex／D1 資料。因為 QQ 指令面板及開放平台舊「指令配置」可能共存，如果清理結果是 no_match 仍不能說已修好。

## 2026-10-11：Cloudflare 實際診斷與保守處理

Cloudflare qqai 部署版本 `9ef32fc9-0039-4bcd-abe7-0de69633e68f` 於 05:34 UTC 記錄 `QQ_PANEL_RECORDS_MISSING`。因此尚無證據顯示 QQ 過期指令已被移除；GitHub CI 成功不代表平台操作成功。

後續修補只放寬已知的 API 封裝層次（直接 `records`、`data.records`、`data.data.records`），仍要求 `records` 必須是陣列。未知格式不執行 PUT 或 DELETE，而是以 `OBJECT`／`ARRAY`／`ABSENT` 等類型產生安全診斷碼，不輸出原始 API 資料及機密。

下一步依更新後 Cloudflare 的錯誤碼確定資料格式；舊版 QQ 發布後台與新式 `/v2/panels` 的資料可能不同，不得將 `no_match` 視為 QQ 客戶端舊指令已消失。
